# Aperture — Repo Map

Self-hosted media recommendation & watch-tracking app for Emby/Jellyfin. AI recommendations via pgvector embeddings. Integrations: TMDB, OMDb, Trakt, Seerr (Jellyseerr/Overseerr), MDBList, JustWatch, n8n, Tavily, fastCRW (self-hosted search + scrape, `packages/core/src/lib/crw.ts`), LLDAP (optional email import, `packages/core/src/lldap/`), any SMTP server (optional outgoing email, `packages/core/src/email/`; newsletters are the one feature sending through it, `packages/core/src/newsletter/`), Index-Translate or any OpenAI-compatible model (optional synopsis translation, `packages/core/src/translation/`).

> **Keep this map current.** Adding/moving/renaming a route, page, core module, or table updates the relevant section here in the same change. Stale entries cause wrong-file edits.

## Repo-wide invariants

Hold everywhere; sections below name them instead of restating.

- **HNSW / `ef_search`** — an HNSW scan returns at most `ef_search` (default 40) rows, and filters pgvector applies after the scan (watch status, country, series, library scope) shrink that further. Any ANN query wanting >40 rows or post-filtering goes through `scopedAnnQuery` (core `lib/libraryScope.ts`): on pgvector ≥0.8 it sets `hnsw.iterative_scan = strict_order` at the default `ef_search` (`scopedAnnSettings`, pure, pinned; the assistant tools `search.ts`, `scoredPool.ts`, `episodes.ts` use it too); below 0.8 or unknown version it falls back to `SET LOCAL hnsw.ef_search = 500` (an unknown dotted option is accepted silently and does nothing). Always `SET LOCAL` in a transaction, never leaking to the pool. Do not raise `ef_search` "for recall": at 500 or even 100 the planner abandons the index and seq-scans every embedding (seconds instead of ms). Iterative scan is approximate (recall ~0.97–0.99) and stops at `hnsw.max_scan_tuples` (20,000), so a very narrow filter can still come back short. `routes/annSettingsCallSites.test.ts` fails on any `hnsw.*` setting outside `libraryScope.ts`.
- **NUMERIC arrives as a string** — `'0.0000'` is truthy, numeric `0` is not: guard scores/ratings with `!= null`, never truthiness. `Number(null)` is 0, not NaN: map NULL to `undefined`.
- **Absent ≠ false** — migration-added fields are absent on older rows and must keep pre-migration behaviour: test `=== true` / `!= null` (`ContentItem.watched`, `evidenceSupportsCause`, `sharedIds`, the preference chain, weight shares, `freeTier`). One exception: absent `aiLanguage` FOLLOWS THE APP LANGUAGE (`languagePreference.ts` says why; the switcher reads the decided `aiFollowsApp`).
- **The web bundle never imports `@aperture/core`** — duplicate tiny helpers (e.g. `src/i18n/localeDirection.ts`). Any constant or threshold decision the UI needs rides in the API response as a decided value, never hardcoded in the bundle.
- **Parallel implementations are mirrored** — `recommender/movies/` ↔ `recommender/series/`, `media/emby/` ↔ `media/jellyfin/`, the two explanation generators. A fix in one usually needs the other; drift is called out where it exists.
- **A predicate used in several places is a pure module with a test** (no DB): `watchedExclusion.ts`, `pending.ts`, `genrePreference.ts`, `logWindow.ts`, `crossMedia.ts`, `jobs/state.ts`, `explanationParsing.ts`, `countryMatch.ts`, `titleMatch.ts`. Copies drift or agree only by being wrong identically.
- **Never threshold a cosine band blind** — cosine bands here are much narrower than they look and differ per population/model. Measure the distribution first; prefer a threshold whose failure is the safe side.
- **Measure per user before reading an aggregate as a mechanism** — a per-user score averaged across users can show a trend no user has (similarity-by-decade read as recency bias; per user it reverses). Low pairwise watch-history overlap is expected even for identical taste in a large library.

## Architecture (30 seconds)

pnpm monorepo, ESM everywhere, no ORM (raw SQL via `pg`):

- **`packages/core`** (`@aperture/core`) — ALL domain logic. `tsc` → `dist/`. Subpath exports: `.`, `/config`, `/db`, `/media`, `/recommender`, `/strm`, `/channels`, `/jobs`, `/watching`. Root `src/index.ts` is a giant barrel (~1090 lines).
- **`apps/api`** (`@aperture/api`) — thin Fastify HTTP layer (port 3456): routing, auth, job orchestration. Handlers call core functions; `src/lib/db.ts`, `lib/logger.ts`, `config/env.ts` are pure re-export shims of core.
- **`apps/web`** (`@aperture/web`) — Vite + React 18 SPA (dev port 3457, proxies `/api` → 3456). MUI 6, react-router 7, i18next (14 locales), d3, recharts. No central API client: raw `fetch('/api/...', { credentials: 'include' })` everywhere.
- **`packages/ui`** (`@aperture/ui`) — shared React components (MoviePoster, StarRating, BaseCarousel, RankBadge, StatusCard, TrailerModal, `getProxiedImageUrl`). Web aliases it to `src/` for hot reload; typecheck/build use `dist/`.
- **`db/migrations/`** — numbered SQL (`0001`–`0216`; `0129` is used twice, tolerated since the runner tracks filenames). Postgres + pgvector.

## Commands

```
pnpm dev                # api + web concurrently (kills stale 3456/3457 first)
pnpm build              # pnpm -r build (topo order)
pnpm typecheck          # builds packages/* FIRST, then pnpm -r typecheck
pnpm lint / validate    # eslint --max-warnings 0 / lint + typecheck
pnpm db:migrate|db:status
pnpm --filter @aperture/web i18n:sync   # propagate new en strings to 13 locales
pnpm --filter @aperture/api docs:api    # regenerate docs/api-reference.md from the OpenAPI document (no DB needed)
```

**Critical:** apps consume the compiled `dist/` of core/ui. After adding/changing any export in `packages/core` or `packages/ui`, run `pnpm --filter "./packages/*" build` or app typecheck fails with TS2305/TS2307.

## Database

- Pool + helpers: `packages/core/src/lib/db.ts` (`query`, `queryOne`, `transaction`). Env: `packages/core/src/config/env.ts` (`DATABASE_URL` required; `@db:`→`@localhost:` rewrite unless `DOCKER_ENV`).
- Migrations: next-numbered `NNNN_name.sql` in `db/migrations/`. Two runners with duplicated logic, both tracking `aperture_migrations`: `packages/core/src/migrations.ts` (API startup, `RUN_MIGRATIONS_ON_START`) and `scripts/migrate.mjs`. Keep them in sync.

## Naming traps (easy to edit the wrong module)

Each entry is the rule; `[F-NNN]` links its evidence in [docs/aperture-forensics.md](docs/aperture-forensics.md) (measurements, how the failure presented, rejected alternatives). **Read the linked section before changing, reverting or arguing with a rule**; the rule alone is enough to write correct code. **A new entry goes here as the rule, its evidence appended to forensics under the next free number. Write for an LLM reader:** one rule per entry, about 1,500 characters at most; fragments are fine; no history, measurements or "the first version did X" (that is forensics); name constants rather than copy their values. A rule that only matters inside one directory goes in a `CLAUDE.md` there (loaded when working in it), with a one-line pointer here. The long-form wording these entries were compressed from is `git show 65962deb:CLAUDE.md`.

- **`discover/` ≠ `discovery/`** (api routes, mirrored in web/core): `discover` = browse people/studios + TMDB-external detail (`/api/discover/*`); [F-001](docs/aperture-forensics.md#f-001)
  - `discovery` = missing-content engine feeding Seerr (`/api/discovery/*`). Third, unrelated: `assistant/discovery/` (web-grounded chat candidates), sources registry `assistant/discovery/sources/` (`WebSearchSource`): Google grounding, Tavily (core `lib/tavily.ts`, `system_settings.tavily_integration`), fastCRW. `gatherFromSources` runs all concurrently and COMBINES them into one structuring pass, never races them.
  - Tavily: errors logged under provider `tavily`; credit balance read live from `GET /usage` (`getTavilyUsage`, parser `tavilyUsage.ts` pure, missing figure = null never 0) via `GET /api/settings/tavily/usage` with the SAVED key only, shown by `TavilyUsageReadout`; nothing stores it, not metered. fastCRW (`sources/crw.ts` over core `lib/crwChatSearch.ts`): on with the integration unless `CrwConfig.assistantSearch === false`. It is NOT analysis retrieval: one engine (first unparked, no cascade, no engine-health recording), ≤ `CHAT_CRW_MAX_PAGES`, 15s page budget, `CHAT_CRW_REQUEST_TIMEOUT_MS` cap (CRW serializes searches, so a running analysis job can push a chat search past it).
  - Reuses only some analysis filters (walls, empty fetches, listed domains, markup/furniture strips) — never `hasNoProse`/`stripNavigationRuns` (a list of linked titles is the answer); links flattened to labels (`cleanChatPageText`), pages trimmed to `CHAT_CRW_PAGE_CHARS`; `prepareChatPages`/`trimPageText` pure, pinned. Chat timeouts are not filed in `api_errors` (`recordTimeouts: false` on `crwSearch`; other failures still are).
- **A new AI role is a list entry, not a union member.** `AI_FUNCTIONS` (core `lib/ai-capabilities/types.ts`) is the one copy; `AIFunction` derives from it. Roles are ALSO a JSON-Schema `enum` on ten Fastify routes (`settings/schemas.ts` ×3, `setup/schemas.ts` ×7) TypeScript can't check — miss one and the role's card shows "No models available". Runtime guards use `isAIFunction`; enumerations iterate `AI_FUNCTIONS`. Never put roles in a SQL `CHECK` (`aiFunctionSchemas.test.ts` fails on a migration CHECK naming 2+ roles); `custom_ai_models_provider_check` (providers) stays. Custom models are keyed `(provider, function_type)`; `getModel`/`getModelsForFunction` go through `modelPool`. [F-002](docs/aperture-forensics.md#f-002)
- **Web Search is Google-only and holds two keys.** `getProvidersForFunction('webSearch')` → `google` only; `AIFunctionCard` shows a label for a one-provider role and auto-corrects an off-list selection. Spare keys are `ProviderConfig.fallbackApiKeys` (a list; the legacy scalar `fallbackApiKey` is read, never written). Anything spending grounding quota goes through `withGroundingModel`/`withWebSearchModel` (core `lib/ai-provider.ts`): walks `getWebSearchAttempts()`, advances only on a quota error, writes every attempt to `web_search_usage`. Limits/cooldowns `lib/webSearchQuota.ts`, counters `lib/webSearchUsage.ts` (day = midnight US/Pacific). `webCandidates.ts` can't use the wrapper and meters by hand via `recordWebSearchCall`. PATCH: omitted `fallbackApiKeys` = leave alone, `[]` clears; the card keeps a saved key by position (`{ keep: n }`, `resolveFallbackKeyEntries`), honoured only while the role stays on the provider it was saved for. [F-003](docs/aperture-forensics.md#f-003)
- **Two "cost" surfaces, only one measured**: `CostEstimatorSection` projects; `InferenceDashboardSection` measures `METERED_PROVIDERS` (OpenRouter, Z.AI) and hides when no role uses one. Capture is in the provider's `fetch` (`createOpenRouterUsageFetch(role)`, core `lib/openrouter-usage.ts`), so new generateText/streamText sites need no instrumentation; `role` is fixed at provider creation and is part of the provider cache key. `feature`/`sessionId`/`userId` ride AsyncLocalStorage (`lib/inferenceContext.ts`) set only in `runJob`, the chat handler and `testProviderConnection`; anything else records `unattributed`. Cost is nullable end to end — never treat missing as zero; the dashboard reports `pricedCalls` separately. [F-004](docs/aperture-forensics.md#f-004)
- **OpenRouter pricing comes from its own catalog**, not `PROVIDER_MAP` (`lib/pricing-cache.ts` has no `openrouter` entry). Use `getOpenRouterModelInfo`, exact id only (`:free`/`:extended` priced differently). `FunctionPricing.pricingKnown` separates free from unpriceable; render unknown as unknown, never $0. [F-005](docs/aperture-forensics.md#f-005)
- **The assistant consumes the recommender's output, not its logic.** Only `getMyRecommendations` touches the pipeline (reads `is_selected` off the newest completed run). `semanticSearch`/`findSimilarContent` are bare pgvector kNN (no novelty, boosts, diversity, slots). Items carry `source` (`ranked`|`twin`|`interest`|`acclaimed`) DERIVED by `pickSource` from `score_breakdown` — never pass the object through: it holds `twinMatch.donorId` and the model must never get an identity it could name. Twin picks carry `sharedTitles` from the reader's own history, resolved batched via `resolveTwinSharedTitles`. Absent `source` = `ranked`. Nothing calls `ContentItemSchema.parse()`; `tool-ui/types.ts` mirrors the schema by hand — update both. [F-006](docs/aperture-forensics.md#f-006)
- **`searchMyRecommendations` = library-scoped personalised search** (`assistant/tools/recommendations.ts`): ANN joined to `recommendation_candidates` of the newest completed run (gives scoring scope + watched exclusion), re-ranked by `blendQueryAndTaste`. Both terms min-max normalised over the fetched pool before blending, never raw; `QUERY_WEIGHT` 0.6; `ANN_POOL_SIZE` (400) via `scopedAnnQuery`. Results carry NO `rank` (`ContentCard` renders any `rank` as a RankBadge; only `getMyRecommendations` sets one, from `selected_rank`). Must call `enrichCardReasons`. The query lives in `tools/scoredPool.ts`, shared with discovery's taste section — never copy it. A new tool needs a `TOOL_PHASES` entry and a line in `prompts/rules/tools.ts`. [F-007](docs/aperture-forensics.md#f-007), [F-120](docs/aperture-forensics.md#f-120)
- **The taste brief personalises SELECTION, never RETRIEVAL.** `discovery/tasteBrief.ts` → `discoveryResolve` → `gatherWebCandidates`, applied only in the structuring pass (`webCandidates.ts` `viewerBlock`, no search tool): may order and tie-break, never add, drop or re-justify. The profile must never reach a search call: `WebSearchSource.gather` takes only the query (`WebSearchContext` deleted — a prompt rule leaked favourites into queries). Tavily ignores the brief but gets a reasoning cue (`include_answer: 'advanced'`, own char budget, separate from `maxContentChars`). `GROUNDING_SYSTEM`: search in English whatever the request language, add a country's own language only for that country's cinema; example uses a `[country]` placeholder, never a named language. Card reasons are written in the viewer's AI language (`enrichCardReasons` takes the user id). Signature titles are grouped by title (a `watch_history` row is an episode). Log `personalized: true` = a brief was built. Known gap: the empty-text retry inside `googleGrounding`'s `PASS1_MAX_ATTEMPTS` loop is unmetered. [F-008](docs/aperture-forensics.md#f-008)
- **The intent router decides whether web search exists at all.** `helpers/routeIntent.ts` classifies a turn `discovery` or `library`; `findCandidatesInLibrary` (the only tool that searches the web or writes card `reason`s) is added only on discovery turns. A request for titles to watch is `discovery` even when personalised; `library` = facts about their collection. `prefilterIntent` is pure, exported, pinned; its match is final and `RECOMMENDATION_HINTS` is checked first. Ambiguity → discovery; classifier error → library. `getWatchHistory` is in `EXEMPT_TOOLS`, so a library turn calling it returns watched titles even with `excludeWatched`. [F-009](docs/aperture-forensics.md#f-009)
- **A discovery turn answers from three directions in ONE tool call.** `findCandidatesInLibrary` returns web picks (`Recommendations`), `seedTitle` neighbours (`Also worth checking`) and, unconditionally, `From your taste profile` — the `tools/scoredPool.ts` search, started before `gatherWebCandidates`, awaited after. It searches `queryText` (the user's words), not a paraphrased concept. `TASTE_SECTION_QUERY_WEIGHT` = `1 - QUERY_WEIGHT` (only `< 0.5` is pinned). Dedupe across all three + seed is load-bearing. `TASTE_POOL` (24) is headroom; watched titles drop before the slice; `TASTE_MAX` (6) keeps one `enrichCardReasons` batch. Server sends it as a carousel (list when alone); with 2+ non-empty sections the client shows tabs and grids every section (`tool-ui/SectionTabs.tsx`). [F-120](docs/aperture-forensics.md#f-120)
- **Watch history is queryable by content.** `getWatchHistory` takes only `type` + `limit`; content questions use the search tools' `watchStatus: 'all'|'watched'|'unwatched'` (`watchStatusCondition`, `tools/search.ts`; semantic path via `scopedAnnQuery`). `ContentItem.watched` is stamped by `annotateWatchedItems` and absent when not looked up (card tests `=== true`). `withUnwatchedFilter` skips a call only when `input.watchStatus === 'watched'`. `director`/`tag` filters use `directors::text ILIKE $n`; `$n ILIKE ANY(directors)` is backwards and matches nothing. [F-010](docs/aperture-forensics.md#f-010)
- **No `language` filter, deliberately** (`languages` is nearly unpopulated); use country (`production_countries`, nearly full). `query` matches literal text in `title`/`overview`, not concepts: style → `semanticSearch(concept)`, facts → filters. `semanticSearch` takes `country` via `scopedAnnQuery`. Demonyms map through `helpers/countryMatch.ts` (values are substrings, e.g. `Germany` matches "West Germany"; unknown input passes through). [F-011](docs/aperture-forensics.md#f-011)
- **The last model step is wasted without a guard.** `stopWhen: stepCountIs(MAX_STEPS)` is checked after a tool step, so a turn that searched every step ended with no prose. `prepareStep` forces `toolChoice: 'none'` on the last step (`stepNumber` 0-indexed). Raising `MAX_STEPS` alone fixes nothing and costs superlinearly (each step resends all tool results). Hitting it logs warn "Step budget exhausted". [F-012](docs/aperture-forensics.md#f-012)
- **`semanticSearch` has no distance floor**, so headings never vouch for results: "Movies closest to …" / "The {{count}} nearest titles in your library", never "matching". Do not add a cutoff without measuring query→item distances (cosine invariant). Broad calls: `format: 'brief'` + an explicit display call is the fix (costs a step). [F-013](docs/aperture-forensics.md#f-013)
- **Enrichment separates "done" from "never asked".** `enrichment_version` records schema version, not which sources answered. `omdb_enriched_at` (`0136`) is stamped only when OMDb was attempted without throwing ("not found" counts; an error retries). One predicate, `enrichment/pending.ts` `needsEnrichmentSql`, for both counts and both selections. Its OMDb clause applies only when OMDb is usable. `clearEnrichmentData` is called by nothing. [F-014](docs/aperture-forensics.md#f-014)
- **A null from the OMDb client means "no entry", nothing else**; everything else throws `OmdbRequestError` (classification pure, `omdb/failures.ts`). OMDb answers 401 for both a bad key and spent quota; only the body separates them → `parseApiError` (`errors/omdb.ts`), also in `testOMDbConnection`. Auth/quota errors can arrive as HTTP 200 + `Response: "False"`, so `isNotFoundBody` is a closed list. A bad key latches for ten minutes; keys `.trim()`ed on write and read. `enrichMetadata`'s `while (true)` loops end only when the selection empties, so an unstamped row must be marked attempted (`attemptedMovieIds`/`attemptedSeriesIds`). [F-015](docs/aperture-forensics.md#f-015)
- **An MDBList stamp (`mdblist_enriched_at`) is a freshness date; an unanswered request stamps nothing.** (1) `MDBLIST_PENDING_SQL` (`mdblist/rules.ts`, pure, pinned) is the one due rule (never asked, or older than `MDBLIST_REFRESH_DAYS`). (2) Enrichment requests go through `sendMDBListRequest` (retries 429/dropped connection, then `MDBListRequestError`) via the `...OrThrow` lookups; for the IMDB GET only 404 = no entry. Lenient `getMediaInfoByTmdbBatch`/`getMediaInfoByImdb` are for Top Picks/on-demand and stamp nothing. (3) Skip only titles a batch left unstamped. (4) Three unanswered batches in a row → `failJob`, never `completeJob`. (5) Dedupe providers by id. Re-asking doesn't re-embed. [F-171](docs/aperture-forensics.md#f-171)

## Recommender / embeddings pipeline (order matters)

## Auth model

`plugins/auth.ts`: `x-api-key` header (wins) or `aperture_session` cookie. `requireAuth` / `requireAdmin` (no bypass). Server-side work acting without a user calls the domain function directly (`routes/jobs/startJob.ts` for jobs, used by the setup wizard), never `fastify.inject`. API-key users are forced `provider:'emby'`, `collectionsEnabled:false`, carry the account's other flags, limited by their scopes (no `admin` scope → `isAdmin` false; no `write` → every writing request refused). Per-feature permissions go through `lib/permissions.ts`, composed as `preHandler: [requireAuth, requireCapability('discover')]`.

- **Sessions are bearer tokens**: cookie = 32 random bytes; `sessions.token_hash` = sha256; `sessions.id` unrelated. 30-day absolute lifetime + 7-day idle (`last_seen_at`, rewritten ≤ every 5 min). `is_enabled` enforced at login and every lookup; `PUT /api/users/:id` revokes sessions when disabling. Login refusal carries `code: ACCOUNT_ACCESS_DISABLED` + server name. `cleanup-auth-state` sweeps expired/idle rows with a 1-day grace (the plugin alone decides a session is dead).
- **Account assumption layers a second cookie, never swaps the session**: `aperture_impersonation` beside `aperture_session`, backed by `impersonation_sessions` (`0159`, one-hour lease, `ON DELETE CASCADE` from `sessions(id)`). `request.user` = TARGET, real admin on `request.impersonation`. Read-only: `impersonationBlocksRequest` (`lib/impersonation.ts`, pure, pinned) refuses unsafe methods except `/api/auth/impersonate/stop`, `/api/auth/logout` and lookup POSTs (`/api/favorites/status/bulk`, `/api/seerr/status/batch`), and blocks the writing GETs `/api/trakt/auth-url`, `/api/trakt/callback`. A getter that writes defeats the guard silently (`getUserSettings` is a pure read now) — audit the call graph. Nothing writes to the target (no session row, `last_login_at`, `updated_at`). The exit lives in `Layout`'s AppBar; its height rides in `--aperture-chrome-top`. [F-103](docs/aperture-forensics.md#f-103)
- **Brute force: two layers on different axes**: `@fastify/rate-limit` on `/api/auth/login` keyed on IP ALONE, plus per-account DB lockout with backoff (`apps/api/src/lib/loginAttempts.ts`). Only `InvalidCredentialsError` (provider 401) counts; an outage returns 503.
- **Deployment posture lives in `apps/api/src/config/security.ts`**: `DEPLOYMENT_MODE` (`direct` default, `proxy`/`tunnel`/`cloudflared`), `TRUST_PROXY`, `HOST`, `COOKIE_SECURE` (on in production, not derived from `APP_BASE_URL`), `API_DOCS` (`public|admin|off`; admin-only in production), `ALLOW_PASSWORDLESS_LOGIN` (production gate over the `allow_passwordless_login` toggle), `SETUP_ALLOW_REMOTE`, `CSP_REPORT_ONLY`; booleans via `envFlag`. `helmetOptions()` and `config/rateLimits.ts` live here so `security.test.ts` asserts what's registered.
- **`TRUST_PROXY=true` trusts anyone's `X-Forwarded-For`** (forged rate-limit buckets, fake local setup access): pin the proxy (`TRUST_PROXY=172.18.0.1`). Unset behind a proxy is worse (one global login bucket; `isTrustedSetupSource` sees everyone as local). `DEPLOYMENT_MODE=proxy` defaults to loopback; explicit `TRUST_PROXY` wins.
- **`config/deploymentPosture.ts` is the one source for "is this exposed correctly"**: boot warnings and `GET /api/settings/deployment` render its `findings` (ids under `settingsDeployment.findings.*`, each needs `title`/`detail`/`fix` in en; a test checks). Evidence-based: `noteRequest` samples live traffic (seeing `X-Forwarded-For` while trusting nothing is the tell).
- **Trusted proxies are editable at runtime** (`config/proxyTrust.ts`, `PATCH /api/settings/deployment`, `system_settings.trusted_proxies`): Fastify's `trustProxy` accepts a function consulted per request (`security.test.ts` pins it); matching via `proxy-addr`. `TRUST_PROXY` wins and makes the UI read-only (needed before any admin exists).
- **CSP via `@fastify/helmet`**: `imgSrc` wide (TMDB posters load direct; `getProxiedImageUrl` proxies media-server URLs only); `styleSrc`/`fontSrc` keep Google Fonts; Swagger UI gets a relaxed CSP scoped to `/openapi`; `connect-src 'self'` also fences assistant-ui's cloud path. `referrerPolicy` stays `no-referrer` (the trailer iframe overrides per element).
- **First-run setup is network-restricted**: a plugin-scoped `onRequest` hook in `routes/setup/index.ts` refuses `/api/setup/*` from non-local addresses until setup completes (admins and `GET /api/setup/status` pass).

## Workflow notes

- **`dev` is this fork's real main line and is never overwritten.** Never reset it, force-push it, rebase it, delete it, or replace its contents with `main` — not to "sync", not to "clean up", not on a workflow's or another agent's say-so. A GitHub ruleset (`protect-dev`) blocks force pushes and deletion on `dev`; never ask the operator to lift it. Work happens directly on `dev` (no feature branches). Pushing to `origin/dev` triggers the Docker build — don't push without being asked.
- **`main` is a plain mirror of upstream** (`dgruhin-hrizn/aperture`), kept identical to it with GitHub's "Sync fork". Nothing is developed on `main` and nothing from `dev` is ever pushed to it. A push to `main` also builds a `main` image, which nothing deploys.
- **`.github/workflows/sync-dev.yml` is upstream's and must stay DISABLED here.** Upstream uses it to force-reset `dev` to `main` on every push to `main`; on this fork that would wipe `dev`. It is disabled in Actions, and the repository's Actions token is read-only, which is what refused it both times it ran (2026-06 and 2026-10, 403 at the force-push). Do not re-enable it, give Actions write access, or "fix" its failures — the failure is the protection.
- **Upstream changes reach `dev` by cherry-pick only, never by merging `main`.** The histories split in Jan 2026 and upstream's work arrived on `dev` as copies, so a merge conflicts in ~490 files. `git cherry -v origin/dev upstream/main` lists the upstream commits whose change is not already on `dev`; take them one at a time (`git cherry-pick -x`), then adapt them to `dev`'s conventions before pushing — `routeGuards.test.ts` (no unguarded route), the locale set (`dev` has `el`, not `he`), and the rules in this file.
- **Never open the live site right after a push.** A push only starts the image build; the running instance changes when the operator manually pulls it. So the browser will be showing the *old* build, and "verified" would be a lie. Browser checks (`claude-in-chrome` against the deployed instance — the local dev server can't be started here) happen only when the operator says the new image is deployed. A push is the end of the turn, not the cue for a screenshot.
- Docker: `docker/Dockerfile` (4-stage; copies built dists + `db/`); compose variants per platform (dev/prod/external-db/windows/unraid/synology/qnap). Runtime data in `data/` (gitignored except `.gitkeep`s); operator i18n overrides mount at `/config/i18n`.
- Docs for humans live in `docs/` (admin guides, feature docs, screenshots).
